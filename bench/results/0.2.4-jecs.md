# mErCS 0.2.4 and jecs 0.11.0: complete CLI measurements

Measured: 2026-10-01; Windows-11-10.0.26100-SP0 / AMD64 Family 25 Model 117 Stepping 2, AuthenticAMD.
Luau: `luau-lang/luau@0.740.0`, executable SHA-256 `9b0181083a16ac8022189ad17fffc1ddc3eced1780f4c631051909e3f5581eb9`.
Baseline: `v0.2.3`, commit `148aff060437ef4689b842534681100e8081ba90`, source SHA-256 `28dbf162704549d8e5651c08f98f18b0030b55d0fa3adc947c160b0d42dd7099`.
Candidate source SHA-256: `16f3cbdca3cc7d9970d13d1ec078ba4e82f6a88e04ec61c154de54a6f1009d47`.

All three library columns were measured again with the same scripts. Five independent
processes per implementation, profile and mode; implementation order rotates between
repeats. The extra jecs-cleanup column belongs only to the long-session profile.
Every cell below is median [min–max]. All raw values, process output, source hashes,
commands and isolated entry-point sources are in [0.2.4-jecs.json](0.2.4-jecs.json).

## Method

- Matrix: `bench/scenarios.luau`, n = 131072, `bench/harness.measure` with three repetitions.
  Each process reports the minimum time per operation and median retained-memory delta.
  Scenario correctness checks run as part of measurement; unsupported features are skipped.
- Synthetic frame: unchanged `bench/frame_scene.luau`. Three batches per query style;
  each returns its reported median of 300 frames after 60 warm-up frames. The helper selects the
  batch with the lowest minimum frame time. Both that minimum and its median are saved.
- Long session: the scenario body of `bench/leak.luau`, one implementation per process,
  seed 777, 5000 frames. Full GC at each 1000-frame checkpoint; the window time includes GC.
- Loop heap growth: 1000 warmed loops over 200 entities, full GC before measurement,
  a weak witness rejecting a completed collection. This is net heap growth, not total
  allocator traffic; a partial incremental collection can still evade the witness.
  The 1 KiB heap-counter resolution gives a 1.024-byte resolution per loop in this batch.
- Hook and reparenting probes: minima of nine batches of 10000 operations. Hook overhead
  is the difference between hooked and plain-delete minima within one process.
- Wildcard-world memory: world plus cached query after a pass and full GC, 20000 entities.
  The diagnostic entry points are embedded in the JSON to preserve their exact versions.

These are descriptive comparisons, not statistical significance tests. Small median
differences should be read with their ranges. Release acceptance against 0.2.3 uses the
separate [P1–P9 paired-control report](0.2.4.md); no release-gate decision is inferred
from a single microbenchmark ratio here. Studio screenshots in the guide remain 0.2.3.

## Reproduction

The ordinary matrix entry point produces the same scenario measurements, rounded for display:

```sh
bash tools/previous.sh v0.2.3
luau -O2 bench/run.luau -a impls=jecs reps=3 n=131072
luau -O2 bench/run.luau -a impls=previous reps=3 n=131072
luau -O2 bench/run.luau -a impls=lib reps=3 n=131072
```

For the exact raw-output entry points and isolated frame/session/probe runs, restore the
small wrappers and runner from the JSON. Run this Python snippet from the repository root:

```python
import json
from pathlib import Path
data = json.loads(Path('bench/results/0.2.4-jecs.json').read_text(encoding='utf-8'))
output = Path('tmp/perf/doc024')
output.mkdir(parents=True, exist_ok=True)
for name, source in data['entrypoints'].items():
    assert Path(name).name == name
    (output / name).write_text(source, encoding='utf-8')
(output / 'run.py').write_text(data['runner'], encoding='utf-8')
```

Set `LUAU` near the top of the restored runner to your pinned Luau 0.740 executable,
then run `python -B tmp/perf/doc024/run.py`. It extracts the exact baseline tag and runs
all five profiles five times in both modes (160 fresh processes). It rejects scenario
errors, missing/duplicate/non-finite rows and source changes during measurement.
The Luau files use the repository aliases and require the pinned Wally dev packages.
